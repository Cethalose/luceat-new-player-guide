Luceat New Player's Guide

This is the durable player guide for learning Luceat. Its first available section is Character Choice Guidance: use it before `!create` or `!levelup` when you want to know what a choice means, what it changes mechanically, and how much complexity it adds to play.

Future guide domains can be added here later; this release is focused on character-building choices.

Start With The Kind Of Player You Want To Be

Luceat asks for choices in a practical order: name, ancestry, class, class skill proficiencies, required class feature choices, background, equipment, spell choices if your class needs them, then final review. Level-up choices appear later through `!levelup` or `!levelup [class]`.

Simple Front-Line Play

Choose Fighter, Barbarian, Paladin, Monk, or Ranger if you want clear combat actions and durable adventuring. Fighter is the most direct starting point; Paladin and Ranger add more spell and support decisions later.

Magic-First Play

Choose Wizard, Sorcerer, Cleric, Druid, Bard, or Warlock if you want spells to shape fights and exploration. These classes demand spell choices and reward planning.

Skill And Social Play

Choose Rogue, Bard, Ranger, Warlock, or a background with strong skill coverage when you want to solve scenes through scouting, knowledge, persuasion, stealth, or investigation.

Luceat is engine-authoritative: the game resolves mechanics, resources, combat targets, spell slots, proficiencies, and persistence. The narrator explains resolved results; it does not invent extra character powers.

Fighting Styles And Feature Choices

Some class features require a named choice before the character can be considered fully configured. Luceat stores those choices and shows them on character summaries.

Fighting Style

Dueling+2 damage bonus.One-handed weapon users who want steady melee damage.

Other Required Choices

Class paths, Warlock Pact Boon, Bard and Rogue Expertise-style choices, and spell configuration can appear during creation or level-up when the active class progression reaches that feature.

Invalid choices do not silently advance the character. Luceat keeps the prior state and asks for a valid supported option.

Current Support State

Candidate-ready mechanics means LUC-39 accounting marks the Luceat choice ready for Board validation with implemented mechanic-family coverage. Data-defined/backfill means Luceat has an accounted profile or replacement target, but it is not counted as a Board-candidate implementation claim. Retired/hidden means the migration gate blocks new public selection or the record is retained only as a Board-visible constraint.

Multiclass Decisions

Use `!levelup [class]` when you want the next level to go into a specific class. Luceat keeps a class-level distribution on your character and prompts only for supported required configuration.

  • Starting attributes are currently broad enough to allow representative multiclass tests, but final eligibility is still governed by Luceat's level-up flow.
  • Wizard multiclass entry prompts spell configuration and persists spellbook, prepared spells, and slots.
  • Wizard level 2 prompts Arcane Tradition before additional spell progression configuration.
  • Bard, Ranger, and Rogue multiclass entry prompt one supported skill proficiency.
  • Previously completed starting-class choices should not be asked again during same-class level-up.

Unsupported Or Deferred Choices

This guide only describes choices Luceat currently exposes or stores. It intentionally leaves out options that may exist in tabletop play but are not supported by Luceat's current ruleset or prompts.

  • Unlisted ancestries, classes, subclasses, feats, spells, backgrounds, and equipment packages are not public player choices in this release.
  • High-level class features may appear in progression data before every downstream interaction has a complete player-facing workflow.
  • Some spell lists include entries above level 1 because they are implemented in the spell catalog, but character creation only asks for what the active spell-selection plan requires.
  • Use `!character`, `!abilities`, and `!spells` after creation or level-up to confirm your saved configuration.
